# Bounded hour matrix host

This executable host composes existing public Core and Environment entries. It is preparation for #195, derived from Phase 0005 Environment acceptance, and carries no recorded real-hour result. The minimum target configurations are Flat 4, Agensh 8 and scaleMAS 6; current code supplies the last two workloads. Flat's hour workload is explicitly pending. This does not approve #196 live capture, and no synthetic capture is substituted.

Use Node 22.19.0 or later. Launching this command can allocate native Workers, create run-scoped Agensh accounts/repository/channel/Board and forward paid Kimi K3 requests. The source/archive/Worker/configuration must first pass independent implementation and operational review under the already authorized run allowance:

```sh
node examples/hour-matrix/main.mjs --config /absolute/path/to/examples/hour-matrix/config.mjs
```

The shipped configuration imports the separately reviewed endurance quota owner and lifetime observation gate from the installed test fixtures. On a tree lacking those dependencies it fails preflight; the short owner cannot silently become an hour owner. Importing the configuration allocates nothing. Each mode factory opens one quota listener before backend construction, uses its stable origin in the frozen backend, and closes it if assembly fails. The matrix is serial. A failed configured mode stops subsequent admission.

Set private host environment variables `SWARMENV_HOUR_IMAGE` (exact `sha256:` Worker digest), `UPSTREAM_URL` and `UPSTREAM_HEADERS_JSON`. Every name here uses the `SWARMENV_HOUR_` prefix. Optional `HOST` defaults to `172.17.0.1`, `LIFECYCLE_URL` to `http://127.0.0.1:8080/v1`, and `ENDPOINT_HOST` to `127.0.0.1`; `LIFECYCLE_TOKEN` is passed privately if required. Only the quota owner sees upstream credentials; Worker backend configuration selects `kimi_proxy/k3` through that owner.

Agensh also requires pre-existing reachable local Gitea and Mattermost services and the pinned native Board source/dependencies: `GITEA_ORIGIN`, `GITEA_OWNER`, `GITEA_TOKEN`, `MATTERMOST_ORIGIN`, `MATTERMOST_TEAM_ID`, `MATTERMOST_TOKEN`, `BOARD_SOURCE` and `BOARD_MYSQL_DSN`. `BOARD_ORIGIN` defaults to `http://127.0.0.1:8660`, and `BOARD_PYTHON` to `python3`. Normal Environment ownership registers new accounts, tokens, channel/repository retention and Board process cleanup; the shared pre-existing service deployments remain their operator's responsibility. This example does not launch a shared Docker stack.

The frozen allowance per configuration is 96 model requests, two concurrent upstream requests, generation target 768 and independently observed maximum 1024 output tokens per request, 98,304 aggregate output tokens, 128 KiB per input and 8 MiB aggregate input. No tool program or synthetic upstream response is injected. Setup is capped at 600 seconds, lifetime work admission at 3900 seconds, actual work at a minimum monotonic 3600 seconds, each turn at 120 seconds, cleanup at 600 seconds, recovery allowance at 300 seconds and margin at 120 seconds. Recovery is reserved, not an automatic retry of unknown writes. Each Bot has 1 CPU/1 GiB, 128 MiB private disk with 8192 inodes, and required export capped at 8 MiB for Agensh and 2 MiB for scaleMAS. Requested provider TTL is the sum of the phase allowances plus 60 seconds (5580 seconds with this freeze); two exact provider observations must independently establish enough remaining lifetime. No global resource listing is used for admission.

Every Bot must be ready and complete one verified baseline contribution before the active clock opens. Each 15-minute window needs at least four distinct actual started/settled inputs with new independently checked business artifacts. Existing public Core status and the same quota receipt are checked at most every 30 seconds while waiting. The final window includes a planned publisher stop and actual durable adoption while the remaining peers continue until the hour ends. The host seals the work clock before cleanup, so cleanup cannot fill an incomplete hour. The final owner must confirm a closed listener, zero active/unknown requests and valid terminal usage; all Core Bots must report stopped execution and complete cleanup.

Agensh writes forty independently checked arithmetic Git files and Board FACTs, merges eight pinned final PRs once, and rereads all eight final files from `main`. The stopped A's retained file is adopted by B after an actual targeted Gitea comment; the normal authenticated event subscription and router must deduplicate it. scaleMAS performs thirty-six started inputs through the real fixed pool, checks immutable arithmetic publications, then verifies ordered post-stop search/visit/citation and preservation. These finite arithmetic tasks establish bounded continuity and collaboration behavior, not mathematical research quality.

`main.mjs` saves raw owner reports only below ignored local `experiments/`, with private directory/file modes, and prints only bounded mode/state/failure/cleanup/duration fields. Model conversations and private output paths are not printed. A full matrix currently exits nonzero because the Flat workload is pending. Trusted local configurations can select `modes:['agensh']` or `['scaleMAS']` for a separately reviewed diagnostic; a subset never declares the three-mode matrix accepted. Injected test clocks always label evidence `controlled`, and the CLI exposes no synthetic-clock option. Controlled tests, native TTL preparation and shorter real probes never count as an actual hour.

Actual long-run configuration additionally requires `SWARMENV_HOUR_WORKLOAD=/absolute/path/to/frozen-programming.mjs`. Its default export must provide `prompt({peer,stage})` returning a nonblank string of at most 4096 UTF-8 bytes, and `verify({peer,stage,submission})` returning strict `true` after checking expected outputs. `peer` is a zero-based numeric index; Agensh stages one through four carry programming while stage zero stays a short baseline, and scaleMAS uses its actual cycle number zero through five. `submission` is exactly the `programming` property read from the actual committed/substrate JSON. Verification waits at most five seconds. The host never executes submitted source. The separately reviewed module supplies the small programming tasks and independent expected answers; this repository adds no benchmark dataset. To select scaleMAS first, an external trusted configuration can import this module's default and export `{...configuration,modes:['scaleMAS','agensh','flat']}`; a subset such as `['scaleMAS']` remains an incomplete matrix with `accepted:false`.

Both hour modes additionally cap actual input concurrency at two. scaleMAS releases this permit immediately after input settlement, before host phase/handoff waits; Agensh shares it across all routers and background events. Cancellation removes queued inputs, and an unknown/failed admitted input fences later admissions. The six-round scaleMAS schedule has 36 inputs and an estimated minimum of 72 model requests if each turn needs one Bash call plus final response; actual internal calls remain counted under 96 with no automatic increase.
