01 · WHY MURM

Write the coordination, not the infrastructure

Most multi-agent projects spend weeks rebuilding containers, gateways, and log pipelines — only to lock into one workflow. murm runs the swarm so you only write the rules.

Swap topologies, not runtimes

Switch between subagents, task pools, peer meshes, or citation graphs without touching the core engine.

Safe isolation by default

Every agent runs in its own container with strict quotas; model keys never leave the host.

Coordinate through customized services

Build and plug in any shared service — task board, mailbox, Git repo, or formal verifier — behind one schema-checked gateway.

Every run, fully inspectable

Sessions, model calls, and tool actions archive cleanly to disk for debugging and fair benchmarks.

02 · MENTAL MODEL

How a swarm runs on murm

You write a Harness (control loop & rules). It steers a Runtime arena of isolated Sandboxes, where Agents share Services through an external Gateway while every Run streams to a Trace monitor.
