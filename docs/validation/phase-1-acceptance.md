# 第一阶段：设计符合性与两小时真实验收

状态：修订草案。本轮以[运行契约](../20261102-agent-task-runtime-contract.md)为准：无任务数量上限，共享Mission可并行，identity在自己的Core认领，三次compaction后下一轮窗口达到80%交接，Git保存失败可以丢弃未保存状态。文档PR不宣称运行效果。

## 1. 每个实现都必须可验收

每项Issue需要三份互相对应的证据：准则/审计问题处理表；[逐项行为表](20261102-phase-1-behavior-acceptance.md)的代码、测试和现象；本Issue两小时匹配运行的主改善结论。不能只看整体利用率或某一条演示就忽略其他实现。

正常工作能力用真实Agent验证。竞争、保存失败、过期写入等难以自然出现的边界，用确定性/故障注入集成验证。需要真实Pi compaction/identity交接的功能不能只由模拟事件证明；自然两小时无事件时可单列预登记真实probe。测试、probe与两小时自然轨迹分别标记，不拼接成一次实验。

## 2. 匹配对照与登记

S1对照直接父实现；S2对照S1；S3对照S2。两侧clean commit，固定原题、fixture/Lean/Mathlib、模型/provider、四Core、7200秒运行上限及总预算。继续已有数学环境；提前成功如实停止，不为凑时长继续消耗。原题未完成而子任务队列空时可继续Mission，不作为自动终止理由。

登记实现/命令、工具schema/提示哈希、预算、identity数、Execution窗口、compaction参数及token窗口测量来源、Git输入commit、允许变化的行为组、主判据、事件覆盖和失败条件。必要接口帮助修改可列入处理差异，不混入prompt调优或额外解题提示。旧代码缺字段时采用同等只读观察或共同可算事实，不把无记录当零。

每项至少一组匹配两小时运行，若复用对照必须实现与配置匹配。报告全部轮次。单对只能说明观察到的现象，不声称普遍统计效果；一次运行内多次调用不是独立实验。目标/阈值在处理运行前冻结，不看完结果调整。

## 3. 判定规则

| 结论 | 含义 |
| --- | --- |
| PASS | 本项符合性修复、必需逐项覆盖和匹配两小时主改善均成立，保护条件满足 |
| FAIL | 有对应机会仍违反预期，或破坏权限、原题验收、资源、身份和隐私要求 |
| INCONCLUSIVE | 必需事件未覆盖、证据不足、对照不可比或未观察到所称改进 |
| BLOCKED | 环境、权限或模型路由未就绪 |

零分母记N/A。没有消息不能证明反馈快，没有重检不能证明迭代修复，没有超限请求不能证明旧cap删除。稀有失败由测试实际发起反例；核心真实行为缺失不能用单元测试替代。单个功能标未覆盖时保留该项，不以总分抵消。

## 4. 正确的观察口径

任务计数没有线上配额含义。未完成Task不会因handoff减少；共享Mission的多个Execution只计一个Task。Checkpoint不结束执行；普通handoff不一定换identity；identity rotation不算新增并行。

按以下口径报告，不要求全部做成在线自动分数：

| 观察量 | 明确定义与限制 |
| --- | --- |
| Mission并发 | 同一共享Mission Task至少两项真实研究Execution的时间区间及数量；不等于独立分工。 |
| 独立分工并行 | 不同普通Task及其实际工作/成果的重叠；有重复或未知则单列，不把同Mission的多个ID当多项分工。 |
| 提案质量与覆盖 | 分母列全部Agent提出的普通Tasks；分别列有效、重复/微任务、仍在执行、材料不足和未能判断。未解决但有可靠反例/失败结果可以有效。未知不能算无效或从报告隐藏。 |
| 有效研究时间 | 依据可见动作和成果支持的研究区间；只可做证据解释，不能从Session存活或RUNNING总长直接等同。 |
| Core占用 | 发现、准备、研究、工具等待、保存和收束分别计；同时列有效研究估计与未知区间。 |
| 可定位的空等 | 已有可认领工作或可继续共享Mission、Agent/资源可用，却因旧独占、二次Core、身份错配或错误列表无法执行的区间；不能凭想象新造工作机会。 |
| 保存与恢复 | 每次保存尝试的成功/失败/未完成；恢复使用的具体前驱Material/commit、恢复后第一项实际工作和重复劳动。 |
| 反馈与轮换 | 每接收Execution分别记录到达、处理和动作；compaction成功次数、当前window_ratio、触发值和新旧identity明确。 |

并行、延迟、资源等before/after使用相同分母和相同观测口径。机会不足不能把合理研究选择判框架错误，也不能据此宣称主现象已改善。总成本和最终数学结果始终另列。

## 5. S1验收

同一Task/Execution中出现至少两条真实FAIL→相关内容修改→新版本检查链，涉及实际不同版本；至少一项诊断被实质处理，新结果仍可FAIL。缓存、重放、空白变动不计修正。

对照定位合同禁用Judge、Response门禁或失败后强制额外工作等实际阻碍，处理运行展示对应路径已恢复。禁止自动修复Task、强制handoff或Response门禁再次阻止合法检查。版本/环境/局部与整题边界通过真实checker集成补足。A01–A05逐项报告。

## 6. S2验收

主现象是共享Mission不再被单执行者锁住，identity能在真实分工和整体研究之间连续工作。匹配运行需要展示共享Mission多Execution各自研究、真实普通Task的提出与独占执行、同Session/Core换任务或返回Mission，以及一条Progress/Git正常接续后继续实际工作的轨迹。全部B01–B10给出对应证据模式。

任务数量、后半程分钟数、50%改善率和N–2N不作固定门槛。正式Issue选择对照中具体阻断及主要before/after判据，例如可定位的共同Mission单人瓶颈或认领/接续中断被消除；同时报告真实独立分工质量与成本。不能以共享Mission四人重复同一推导声称非重复并行提升。

超过旧数量限制、普通Task竞争、handoff不消除责任、权威计数、保存失败等用回归构造反例；真实运行汇总所有实际发生的拒绝和保存。S2只要求基本Git/Progress与主动handoff，不要求S3自动compaction轮换已经实现。

## 7. S3验收

主现象是证据在当前执行中真正改变工作，并在接续后继续生效。至少包含运行中反馈和跨执行未处理反馈两条不同链，及依赖已有成果继续研究的实际接续。对照定位漏处理、迟处理或重复恢复，处理运行消除对应问题，逐条列决定与动作而非仅delivered。

C01–C06逐项覆盖。共享Mission的一项执行处理消息不代替另一项确认；取消/轮换只撤销相应Execution。第三次compaction后低于80%仍继续、达到80%交接、第四次被阻止、新identity从有效快照继续，都要有明确结果。边界比例用I，至少一次真实阈值轮换用R；不足时单列真实受控probe，不偷改两小时配置制造自然效果。

保存失败不算成功接续，但应有界停止并从最后有效状态/输入继续；这条失败容忍不能成为正常保存经常失败的借口。正常测试需成功恢复，故障测试需不阻塞且不误报，两者分别通过。处理和恢复延迟上限在Issue开工前登记，之前120秒/300秒仅为未批准候选值。

## 8. 通用保护与验收包

不修改原题/checker/环境，不增加隐蔽预算，不将数量门槛写入Agent prompt。包括选择、准备、协调、保存、恢复、失败和Judge的全系统消耗均报告，未知项明示。

PR附件包含全部运行身份、before/after、逐项行为表、符合性处理、回归结果、真实/受控事件链、未覆盖和最终判定。证据用commit、相对路径、事件/记录ID、Material/commit/CheckResult引用，不发布原始对话或证明。所有历史报告仍按当时实现解释。

两小时未解出不自动否定机制修复，通过机制不等于数学能力提高。每项实现都可观察，不表示每项都是新的优化指标；必要的trace与断言优先复用现有记录，避免为验收另建庞大监控框架。
