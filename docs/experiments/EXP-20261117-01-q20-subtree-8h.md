## Operator supervision

A separate user service runs the private launcher and observer after the initiating
terminal closes. Its policy is `Restart=no`, `KillMode=mixed`, SIGTERM to the
supervisor, 30-minute shutdown grace and an 11-hour outer service guard covering
research plus cleanup/analysis. The research runner itself enforces eight hours.
The supervisor forwards stop requests as SIGINT to the active child, allowing
existing runner cleanup. It never restarts a run, modifies Workspace, injects
Agent instructions or performs model calls. Normal runner completion triggers
the full experiment analyzer (32 GiB Node heap ceiling), followed by provider
lookup and checker-journal cleanup observations. Completion is recorded privately;
automatic output remains pending semantic review.

Every minute, read-only snapshots record Task/Bot states, Judge classes,
Materials/consumptions and main/target hashes. At four hours the current snapshot
is saved separately. The supervisor requests graceful stop for three consecutive
completed Judge **infrastructure failures**; source failures and request rejections
are ordinary feedback. It also requests stop if the runner/cleanup exceeds
8h30m. Observation-read errors are recorded as unknown, not silently classified
as proof failure. Integrity or infrastructure failures require diagnosis and a
resolved repair/review batch before another formal run. Mere lack of root
completion at four hours does not trigger a new algorithm or reset the Mission.

The launch gate binds two independent PASS reviews to deployment, launcher,
supervisor and service-start hashes. Logs, checkpoints, raw Agent work and
completion metadata remain in ignored operator storage. No automated GitHub
message or claim of scientific acceptance is generated from activity counts.
