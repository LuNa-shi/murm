## Analysis

**Observed sequence.** For Core 1, Task
`af43a475-59a2-4c52-83fc-be75732637bf` was claimed at 11:32:42.121.
The Agent's 20-second `task_take` shell command timed out; its next model
request received local gateway `bot_not_admitted`, and `agent_settled`
arrived at 11:33:02.168 (Agent log line 918). Execution startup completed
at 11:37:43.977. No working continuation was sent before the watchdog stop
at 11:39:52.633. The other three initial sessions settled before their
Executions started as well (Agent log lines 1100, 1142 and 1374).

**Supported explanation.** Public context is 83 files / 11,602,626 bytes.
At the pinned runtime, `OpenSandboxManager.syncWorkspace` sends files through
serial shell RPCs with 65,536-character base64 chunks. Read-only inspection
during the run observed increasing copied file/byte counts, and all initial
copies eventually completed. This is preparation overhead, not a Lean proof
failure or an upload deadlock. `BotModelAccess` intentionally admits model
calls only for UNBOUND selection or ACTIVE work, so PREPARING requests are
rejected locally; the 403 is not evidence of upstream model unavailability.

The same-identity binding callback in `putnam-runner.js` begins
`waitForSettled` only after preparation. Its default cursor starts at the
current record count, missing the already-recorded settlement. A local
zero-model-call probe using the real `AgentCoreSession` reproduced timeout
with that default, while preserving the pre-turn cursor returned settlement
immediately. This establishes the narrow missed-event behavior; it is not a
verified end-to-end fix. In the natural run the watchdog terminated each
initial Execution after roughly two idle minutes, before the nine-minute
turn wait could expire. The fault remains unfixed in this benchmark-only PR.

**Parallelism limits.** Four independently chosen Tasks and overlapping
preparation demonstrate task decomposition and resource use. They do not
demonstrate useful proof parallelism. The summary's maximum active-Core count
of four includes discovery/turn occupancy; all accepted model requests were
selection requests, with no downstream proof artifact. There is no matched
single-Agent FLT observation, so neither speedup nor slowdown can be estimated.
Repeated fresh Bots also repeat public-context transfer and selection cost.
