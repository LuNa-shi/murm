## Analysis

**Parallel contribution is demonstrated; speedup is not.** Several Cores built
separate checked modules, and later Tasks imported and called earlier results.
The dependency chains establish more than concurrent activity or Material
publication. There is no matched single-Agent baseline, so no quantitative
parallel advantage can be estimated. The original protocol flag additionally
prevents treating this as an unqualified formal comparison.

**The bottleneck is convergence on the root, not merely producing lemmas.**
Thirty-four locally completed Tasks and 27 helper modules coexist with an
unchanged root and no Mission submission. Much work establishes conditional
representation interfaces or curve arithmetic. The missing connection between
those interfaces and the actual Galois arithmetic remains open. This is not
proof that the public problem is unsolvable: the separate complete private
179-file witness passed the final checker before the run. It does show that
syntactic compilation context and a solvable target do not guarantee that the
current Swarm can construct the necessary research plan within an hour.

**Formalization and task transition costs are visible.** The late run spent an
extended interval generating candidate revisions while main remained at 0.116,
then merged new work at 0.146. Source failures include type mismatch, unresolved
goals, missing constants and instance synthesis, rather than checker outages.
The four-Core limit does not prevent frequent discovery/preparation turns.
The closeout window bars new Judge/apply/merge work; new Tasks taken in the last
seconds cannot complete useful execution before the deadline. These observations
identify possible research/design questions, not authorization to change the
core algorithm or lifecycle policy.
