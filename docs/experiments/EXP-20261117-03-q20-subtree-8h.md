## Operator supervision

A separate user service runs the private launcher and observer after the initiating
terminal closes. Its policy is `Restart=no`, `KillMode=mixed`, SIGTERM to the
supervisor, 30-minute shutdown grace and an 11-hour outer service guard covering
research plus cleanup/analysis. The research runner itself enforces eight hours.
The supervisor forwards stop requests as SIGINT to the active child, allowing
existing runner cleanup. It never restarts a run, modifies Workspace, injects
Agent instructions or performs model calls. Normal runner completion triggers
the full experiment analyzer (32 GiB Node heap ceiling), followed by provider
lookup and checker-journal cleanup observations. Completion is recorded privately;
automatic output remains pending semantic review.

Every minute, read-only snapshots record Task/Bot states, Judge classes,
Materials/consumptions and main/target hashes. At four hours the current snapshot
is saved separately. The supervisor requests graceful stop for three consecutive
completed Judge **infrastructure failures**; source failures and request rejections
are ordinary feedback. It also requests stop if the runner/cleanup exceeds
8h30m. Observation-read errors are recorded as unknown, not silently classified
as proof failure. Integrity or infrastructure failures require diagnosis and a
resolved repair/review batch before another formal run. Mere lack of root
completion at four hours does not trigger a new algorithm or reset the Mission.

The launch gate binds two independent PASS reviews to deployment, launcher,
supervisor and service-start hashes. Logs, checkpoints, raw Agent work and
completion metadata remain in ignored operator storage. No automated GitHub
message or claim of scientific acceptance is generated from activity counts.

## Analysis

### Parallel progress and value allocation

Independent audits reconstructed 1645.10 Core-minutes of authorized
responsibility within 1912.11 available Core-minutes: mean responsibility
concurrency 3.441. This is not CPU utilization or mathematical productivity.
Check/merge waits overlap 898.78 Core-minutes, 54.63% of responsibility time;
these are a subset, not an additional cost to sum with responsibility.

The collaboration is more than concurrent activity. Separate coordinate,
coprimality and cubic-residual tasks exposed a shared Somos/Ward premise;
a successor proved it, and later coordinate and differential tasks directly
used the result. Another successor read and applied unmerged absolute-inertia
work, repaired endpoint instances, checked and integrated it. This demonstrates
useful parallel contributions and continuity, without establishing a speedup.

Resource coverage remained incomplete. All Task priorities were zero and no
explicit Task relations were registered, although code and Material chains
were real. Public Task contracts did not directly undertake the actual Frey
local-character arithmetic bridge after it was identified at 04:39. Later
pairing/eigenvector and averaging work addressed algebraic sufficient
conditions, not that missing arithmetic. There is no evidence that the
allocation selected the highest-value remaining work.

Feedback grew slower as the project grew. PASS checks rose from a first-hour
median of 15 modules / 26 seconds to a last-hour median of 90 modules / 144
seconds. In the last two complete hours, DONE increased from 6 to 9 while
completed checks fell from 35 to 29. The final increase in DONE includes
closeout and differently sized responsibilities; it is not a mathematical
speed measurement. No same-revision check-strategy control isolates the
causal contribution of project size or proof complexity.

### Checker feedback and recovery

All 26 recorded crashes retain their original classification. Fixed-tree
replays identified Lean panics in an early environment probe and internal
heartbeat exhaustion in later candidates; generic retryable infrastructure
feedback concealed actionable source locations. Some later errors have no
captured detailed cause and remain unknown. Eleven additional starts retried
an unchanged fixed input after a crash, occupying 20.88 checker-process
minutes. These intervals overlap and are not a measured Mission delay.
Ordinary source failures were not all classified as waste.

The affected seventh-index and differential candidates later recovered.
The seventh-index proof replaced broad simplification with explicit equations
and bounded simplification rules; its complete proof passed and was merged.
The last research hour had no crashes. Earlier diagnostic-only API PASS
results were excluded from mathematical progress; later recovery does not
rewrite the earlier failed attempts.

### Protocol and closeout defects

The original `workspace_boundary_violation` is an Execution audit label, not
a filesystem-access report. Two never-started Executions ended under the
existing `selection-budget` path without Workspace references; the audit's
preparation-failure predicate omitted this case. No duplicate non-null
Workspace reference was found. This finding is not evidence of answer
exposure, nor a new exhaustive audit of every interaction.

Cleanup exceeded the original 30-second reporting grace and produced seven
timeout records. Already admitted public Workspace reads remained in a shared
repository queue after shutdown, then returned stopping errors as late as
10:50:09. Eventual resource recovery is verified but does not erase that
historical timeout. The exact contribution of each lock holder is unknown.

The automatic analyzer separately failed on a large raw-log collection.
Independent final audits cover specified mathematical, continuity and timing
questions; they do not substitute for successful full analysis. Any repaired
reanalysis must use a separate output location and remain labelled as a later
analysis of this invalid run.
