## Analysis

The run establishes that a single independent solver, using the existing real Task/Core/Bot/Execution/Workspace and no Task/Material permissions, could reach trusted acceptance on B1. It does **not** establish a valid Pass@1 experiment: the orchestration failure invalidated its runner report, and the final observation was deliberately shortened. No success-probability estimate or controlled comparison with historical Swarm follows from it.

The source-backed cause is acceptance ordering: `IdentityTaskLoop.stop()` fences a live Execution, so invoking it before host finish makes the intended closeout impossible. A regression using the real IdentityTaskLoop, Runtime and Bridge reproduced the Bot becoming CLOSING before finish. Runtime `c9748d5` keeps the solver loop alive until host finish; existing Mission-stop and fixed-attempt guards prohibit new discovery, and final cleanup still stops the loop. A second review finding was addressed in `0619f0d`: the host finish awaits the existing run/closeout deadline, and its delayed promise remains tracked for bounded cleanup. These fixes do not change Swarm's default acceptance path, solver prompts, fixture or verifier.

Controlled regressions now verify actual accepted solver Task DONE and Bot CLOSED, ordinary incomplete finish, existing Swarm closeout, and delayed finish timeout with retained pending-cleanup evidence. Spec and Standards re-reviews passed at `0619f0d`. These are implementation validation, **not a retrospective repair of this experimental sample**. No real-model rerun was performed after the fix. Final full-suite validation at `0619f0d`: **642 tests, 630 pass, 12 conditional skips, zero failures**. The rebuilt image `swarmenv/agent:issue129-0619f0d` (`sha256:a74dc9919f798428a2be2cfeac5ce3f421476963110ce0cd2a6fcc4f3d21cb1f`) passed both worker contract tests and the disk quota/Landlock probe.
