Every Agent needs to edit files and run shell commands safely. A **Sandbox** places each Agent inside its own isolated container and private workspace so it can never damage the host or overwrite another Agent's files without permission.

By default, `murm` provisions containers through the open-source **OpenSandbox** runtime (`murm setup --mode local` sets up a managed local instance in one command, or you can connect to an existing remote service), and also accepts a custom **Sandbox Provider**.

## What every Sandbox provides

When `runtime.spawn()` boots an Agent, `murm` allocates a container through the **OpenSandbox API** or a custom **Sandbox Provider**:

- **Isolated private workspace**: each Agent gets its own `/workspace/project` with verified CPU, memory, and lifetime limits.
- **Worker supervisor**: a lightweight supervisor inside the container manages your chosen executor (Pi, Codex, or an image-installed external adapter), pauses writers during file syncs, and streams session and artifact archives before shutdown.
- **Default OpenSandbox API policy**: manages containers over the authenticated OpenSandbox API with verified CPU and memory limits, working cleanly for both local and remote deployments.

## Configuring `createSandbox()`

```ts
import { createSandbox } from '@luna-shi/murm';

// Immutable, reusable sandbox config (defaults to the OpenSandbox API policy)
const sandbox = createSandbox({
  // OpenSandbox Lifecycle API URL (`murm setup --mode local` binds localhost:8080)
  lifecycleBaseUrl: process.env.MURM_LIFECYCLE_URL ?? 'http://127.0.0.1:8080/v1',

  // Bearer key for authenticated OpenSandbox servers (auto-generated by `murm setup --mode local`)
  apiKey: process.env.MURM_LIFECYCLE_TOKEN,

  // Optional: per-container CPU, memory, and lifetime limits (default 3600s)
  resourceLimits: { cpu: '2', memory: '2Gi' },
  timeoutSeconds: 3600,
});
```

### Common deployment options

- **Reuse CLI connection defaults**: call `resolveSandboxConnection()` on the trusted host to inherit the exact same Lifecycle URL, local token, and image defaults used by the `murm` CLI.
- **Remote or proxied OpenSandbox**: set either `endpointHost` (override returned Worker hosts) or `useServerProxy: true` (route through the OpenSandbox server proxy).
- **Custom Sandbox Provider**: pass `createSandbox({ provider, timeoutSeconds })` to plug in your own container or microVM platform without touching Runtime or Harness code.
- **Optional strict local isolation**: when you need **measured `tmpfs` disk quotas, live shared mounts, or local UID egress allowlists**, pass `isolation: { network: 'local-docker', disk: { bytes: 64 * 1024 ** 2, inodes: 4096 } }` (requires same-host rootful Docker and Landlock ABI 5+).

### Worker images

- **`workerImageFor(executor)`** returns the matching single-executor Worker image tag.
- **`DEFAULT_WORKER_IMAGE`** points to the dual-executor Worker image bundling both Pi and Codex.
- If a specialized role needs extra toolchains (such as Lean or custom compilers), build on top of the official image and set `image` on that role's [Profile](agents.md).
