# 14. Native Agensh Lean experiments

Issue [#157](https://github.com/LuNa-shi/SwarmEnv/issues/157) uses an independent Agensh team. Its workers run the upstream Pi 1.4.0 ACP adapter. Each worker chooses its next action, uses Gitea branches and PRs, reads Mattermost and the shared context board, and receives the native router's turns and tool-result notices. The SwarmEnv Task and Bot loops do not run in these worker containers. The Git submodule pins the complete upstream implementation at 2dae4e14a653da48549fd9aa093f834841475d6c. A staged copy adds one task pack. The ProgramBench task definition supplies the coordination defaults described in the [approved design](../phases/0004-agensh-lean-replication.md).

## Stage and start

Initialize the submodule. Build the pinned upstream board and mini-router Dockerfiles as swarmenv/agensh-board:157-2dae4e1 and swarmenv/agensh-mini-router:157-2dae4e1. Build the upstream agent base with its Dockerfile.base and the worker from agent/Dockerfile with the pi target, PI_CLI_VERSION=1.4.0, AGENT_BASE_IMAGE set to that base and TASK_IMAGE=python:3.12-slim-bookworm. Retain the actual image IDs in the run manifest. Bootstrap and secret-service are built by Compose.

Run [stage.py](../../integrations/agensh/stage.py) with the locked deployment JSON, pinned fixture checkout, new ignored run directory, trusted private operator provider catalog, task ID, worker image and unique profile suffix. It creates the private directory exclusively, checks out the upstream SHA, installs the pack, generates an upstream profile, and binds Pi version, model and concurrency in identity.json. The private input manifest additionally pins staged pack and integration source bytes, tracked upstream state, deployment and verifier lock, original statement, provider route, generated profile/overlay, and worker/service images. Startup checks those identities again before the research window. The launch clears inherited lifecycle overrides and disables planning. It fails on unknown tasks, missing images, an unsupported provider, or reuse of a run directory. The public checkout is readable by container service UIDs. Operator secrets reside in the private run directory. Short Putnam uses two workers and at most half an hour. A replacement pilot sets --research-seconds to the remaining allowance after prior active research windows. Q20 uses four workers and eight hours. Both select gpt_proxy/gpt-6.1-sol, high reasoning and upstream context/compaction defaults. Metering stays enabled with zero cumulative-token limit. No token target participates in task selection.

The generated Compose overlay mounts only the pinned Lean toolchain, compiled allowed libraries, public Mathlib source, and the local checking command into workers. lean-check takes one Lean file relative to the directory containing the target, elaborates it and writes an olean beside it for subsequent imports. This is interactive diagnostic evidence. Gitea records server-side ref updates. The upstream egress service alone receives the operator provider credential, removes the native local authorization header, attaches the trusted credential to the exact configured Responses endpoint and checks the model. Redirects are disallowed. Workers receive the native per-worker/local route. Keep upstream credentials and proof material out of published logs.

Run [start.py](../../integrations/agensh/start.py) on the staged directory. It checks the matrix, native profile and worker image, marks this launch, and forwards signals to the original team driver. The first native wake log line opens a read-only deadline for model requests. New requests close at the time limit. Requests already admitted may settle later. The driver owns service bring-up, worker ramp, watchdog, reminders, export, quiescing Pi/router processes, archive verification and teardown. The output directory already existing aborts a fresh native start. If archives are incomplete, the upstream driver may preserve the containers for recovery. Verify physical cleanup and record setup, research window and settlement separately. A lost operator process or container fault needs a run-specific state and resource check.

## Seed, final assessment and observation

The pack hooks call [domain.mjs](../../integrations/agensh/domain.mjs). Prepare reads the pinned public fixture with the same SwarmEnv loader as the benchmark runner, verifies Git identity and content, and copies only the target and allowlisted public context into a new seed directory. The driver pushes its contents into a fresh Gitea repository. It creates the root issue and posts the briefing through its normal wake path. The pack omits a planner and issue-assignment sync. See the [prompt texts and composition](08-prompts.md#native-agensh-math-team).

Export fetches the exact main ref into a fresh operator-private bare repository, resolves the commit and tree and writes export.json. Git authentication is process-local to the fetch. The final checker consumes the Git blobs without checking out or executing candidate-provided build scripts. Only regular file entries are accepted. The configured bounds are 10,000 entries, 2 MiB per file and 16 MiB total. Evaluation revalidates fixture, input tree and checker lock, calls the fixed-declaration comparator/kernel checker and stores the full verdict and identity in acceptance.json. A mathematical rejection produces a completed research assessment. An exceptional, unavailable or incomplete checker produces an engineering failure. Each receipt is write-once; diagnose an interrupted hook against its preserved directory.

[observe.mjs](../../integrations/agensh/observe.mjs) is an operator-only process. Pass the prepared run directory as its sole argument. It reads the fixture, problem ID and deployment from the same launch profile as the team. It opens an independent mirror and locked verifier, records readiness, polls public refs every 15 seconds and stores observed tips, ancestry, changed paths, timestamps and completed check results in observations.ndjson. First-parent changes yield module diagnostics. Main target changes trigger a fixed-goal check, also reconsidered on later main revisions if the target differs from the fixture. Final checks receive queue priority. Sampling ends at export or operator SIGTERM. Checks may settle later. Sampling, first visibility, checked-at time, statement-level reuse and correctness are distinct measurements. Short-lived refs between polls can be missed; use retained server ref logs, messages, conversations and Git objects to audit gaps. Module diagnostics alone do not determine mathematical milestones. [Experiment evidence rules](../workflows/experiment.md)

The SwarmEnv test command selects the repo-owned test/**/*.test.js suite explicitly. Upstream/native tests use their own dependencies and commands. Ignored research snapshots are outside test discovery.

## Seymour comparison with EXP-20261120-02

The openai/math entry selects four native workers, Pi 1.3.0, gpt-6.2-sol and medium reasoning. The launch profile sets a 500,000 effective context window and a 128,000 output-token ceiling. Seymour staging verifies the original public declaration, source digest, fixture commit, Mathlib revision and the full EXP-02 checker configuration against its canonical lock digest. An added context manifest or instructions file fails staging. The pack rechecks that deployment boundary during seed preparation. The optional --seymour-paper switch adds only benchmark/paper.pdf and benchmark/paper.txt to the same public goal. The host reads the repository-owned manuscript through the benchmark context reader, pins manifest 7154d525, and verifies both regular-file paths and content digests before native services start. Manifest or payload drift aborts preparation. The kickoff identifies both paths; the native driver distributes the fresh seed and kickoff to the peers. The evaluator retains the paper-progress rubric separately. The worker overlay supplies the matching Pi catalog value from the baseline while leaving the native model loop and communication code in the upstream image. The egress route admits the staged model. Existing route files retain the original model default.

For this task the four-hour wall clock starts when the driver records launch.json, before native setup. At first wake the egress proxy opens until that original deadline. At the cutoff a timer writes finalize through the native control file, which leads to export and evaluation. The operator also checks for a trusted receipt against the current Gitea main tree and closes the window on that outcome. The socket bridge, initial prompts, local diagnostic command, wake stagger and handoff remain native Agensh. Ordinary diagnostic module checks and fixed-target evaluation use the operator-side locked deployment.

Seymour mounts the locked compiler bin/lib read-only. For each configured dependency library the host copies ordinary files into a numbered per-run directory, sets directories to 0755 and files to 0444, rejects symlinks, and bind-mounts the copy read-only. Staging and launch compare path and content digests against the original locked libraries. The original permissions remain part of the operator checker lock. Before opening the clock the actual worker image must prove a small Mathlib example as native Pi UID/GID 10000:10000 with the mounted tool and libraries, in an isolated scratch repository on an offline container. Failure aborts startup. The disposable container exits before research. On interruption or a 180-second probe timeout the launcher also removes its exact recorded container ID. Older staged directories without copies still undergo the UID probe when started with this launcher. Mathlib source for browsing comes from a private per-run export of regular Lean files at the pinned public Git revision. The snapshot excludes working-tree changes and untracked files. Startup verifies its content fingerprint and checks the live verifier, compiler and library artifacts before creating worker services or opening the research clock.

For Seymour, lean-check resolves the requested source against the Git worktree and the fixed directory containing the original theorem. It rejects tracked Lean sources outside the target module layout, copies regular tracked and eligible draft sources into a new temporary Lake project, rejects symlinks and the baseline verifier’s reserved module names, and supplies inert package metadata backed by the approved compiled libraries. It builds the requested module and its imports from source in that isolated project. The current directory determines only how the filename argument is resolved. Stale .olean files, ambient Lean paths and candidate Lake configuration do not enter this build. It discards the temporary project on return, reports build failures to the caller and limits each build to 600 s. Timeout or termination kills the owned Lake and compiler process group before temporary cleanup. This command gives local module diagnostics. Acceptance still requires the independent fixed-declaration Judge on an exported tree. Putnam and Q20 retain the standalone Lean command described above.

The Seymour deployment names the historical checker checkout. Before loading that verifier, the adapter verifies its exact baseline Git commit and clean Judge sources. The operator mounts the baseline checkout read-only at the absolute paths pinned by the old checker lock, inside a private mount namespace, then drops back to the ordinary experiment user. Research containers receive the public target and allowed Lean libraries. The baseline checkout and historical solutions stay outside their mounts. The paper arm distributes its two manuscript files in Git. A separate operator samples service liveness, usage, Git and Judge evidence every minute and records ten-minute windows with individual worker responses and public activity.

### Running the four-worker Seymour comparison

On a host with the pinned native service images and EXP-02 artifacts installed, set `DEPLOYMENT` to the locked operator JSON, `FIXTURE` to the original fixture checkout, and `PROVIDER_CATALOG` to the operator-only Responses catalog. Set `EXP_ID` to the new registered experiment ID and `PROFILE_SUFFIX` to a fresh lowercase alphanumeric suffix. Run these commands from the repository root.

```sh
git submodule update --init third_party/agensh
RUN_DIR="$PWD/experiments/$EXP_ID"
python3 -B integrations/agensh/stage.py \
  --task oai_seymour_second_neighborhood \
  --deployment "$DEPLOYMENT" --fixture "$FIXTURE" \
  --provider-catalog "$PROVIDER_CATALOG" --run-dir "$RUN_DIR" \
  --worker-image swarmenv/agensh-pi:157-seymour-pi130 \
  --profile-suffix "$PROFILE_SUFFIX"
```

This invocation selects the challenge-only arm. Its seed contains the original Lean target. For an authorized paper-arm comparison, add `--seymour-paper` at staging. The profile and private input manifest fix the arm before worker startup.

In the operator environment where the exact EXP-02 checker checkout is mounted at the paths recorded in its artifact lock, start the following two processes in separate terminals or supervised services. Keep the same working directory and absolute `RUN_DIR` for both. The observer records `observer_ready` in `observations.ndjson` after it validates the verifier. Start the team once that record exists.

```sh
node integrations/agensh/observe.mjs "$RUN_DIR"
```

```sh
python3 -B integrations/agensh/start.py "$RUN_DIR"
```

The driver enforces the four-hour deadline. For early acceptance an external monitor must match a fixed-goal PASS's checked tree to the **current server main tree**, close model admission by atomically replacing `clock/deadline` with the current Unix time, then write `finalize` to `out/oai_seymour_second_neighborhood/control`. The final exported commit, tree and locked verdict appear in `export.json` and `acceptance.json` under that task output directory. Verify worker archives and remaining profile containers after the driver exits. A module-mode PASS can occur on the original goal with its proof hole still present.
