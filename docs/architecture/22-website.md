# 22. Public documentation website

The Astro application in [website/](../../website/) publishes the murm landing page, documentation overview, mental model and architecture guides, five Harness guides, a Quickstart, and API, TypeScript, and deployment references. Its npm package has a separate lockfile. It does not start a Runtime or connect to a Service, model provider, or private Run.

## Build and render

Use Node.js 22.23.4 or later. Run `npm ci` and `npm run dev` in `website/` for a local preview. `npm run build` writes the static output to `website/dist/`. `BASE_PATH` defaults to `/` and selects the URL prefix. For the repository site it is `/murm`. `SITE_URL` defaults to the owner’s GitHub Pages origin. These values are build inputs. Update them and rebuild when deploying under a different host or prefix.

The content loader reads `src/content/docs/` (English) and `src/content/docs-zh/` (Chinese), validating each page's title, description, section, and order. Astro prerenders the English and Chinese landing pages (`/` and `/zh/`) plus one documentation route per content slug under `/docs/` and `/zh/docs/`. The shared layouts use those fields for page metadata, navigation, the current page marker, a top-right language switcher linking each page to its counterpart locale, and active table-of-contents tracking. Copy page writes the title, description, and rendered article text to the clipboard. It excludes the code-copy controls and displays success or failure on the button. Relative Markdown links resolve from the rendered page. The URL helper adds the configured base to generated navigation, search destinations, and the favicon. Astro bundles local font assets and inline SVG landing schematics. The public directory supplies the favicon and verbatim font license notices. Departure Mono’s notice and font come from the [upstream font assets](https://github.com/rektdeckard/departure-mono/tree/75152a3f1e6dacdd248a6c397c97dbf27e33eea0/public/assets). The other notices come from the locked Fontsource packages. Update the included notices when changing the corresponding fonts.

The browser handles the landing page diagrams, Harness selector, theme, and site navigation. Search indexes documentation titles, descriptions and sections for the current locale at build time and orders them by the content order field. Opening search shows up to eight pages. Typing filters the index locally. Search renders results and empty-query feedback as DOM text, uses only built documentation destinations, and sends no queries to a server. Escape or backdrop click closes it and returns focus to the navigation button. The theme preference stays in browser storage. The site writes no server-side session state.

## Publish and recover

The [Pages workflow](../../.github/workflows/deploy-website.yml) starts after a push to `main` that changes the site or its workflow, or from manual dispatch for a selected ref. GitHub Pages uses the GitHub Actions source. The `github-pages` environment applies its configured branch policy to each deployment. The workflow reads the site origin and base path from Pages, runs a locked Node 24 build, then uploads `website/dist/` as a Pages artifact. The deploy job runs only after the build succeeds and publishes that artifact using the repository Pages permission and an OIDC token. Each successful deployment replaces the entire published site at the same URL. A deployed artifact must include both locale trees to serve both locales. Deployments share a concurrency group. No npm package publish or sandbox setup runs in this workflow.

Installation, build or environment errors surface in the corresponding Actions job. A successful deploy job records the public URL. A failed build leaves the previously published site available. After fixing a failed deployment, dispatch the workflow on `main` and verify both landing pages, a nested documentation route in each locale, and a static asset under the configured base. The package and local build output are independent of the live deployment history.
