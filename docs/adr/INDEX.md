# Architecture decision records

ADRs preserve the context and tradeoffs behind accepted design decisions. They are not a second product specification and do not override human-approved GitHub Issue requirements or experimental evidence.

| ADR | Purpose |
|---|---|
| [0017: Task-centric shared Mission](0017-task-centric-phase1-contract.md) | Earlier rationale for shared Mission and independent Tasks; current code/evidence must be verified separately |
| [0018: GitHub Issue-led engineering workflow](0018-issue-led-engineering-workflow.md) | GitHub Issue is the sole requirements authority, Matt engineering skills define procedure, STATUS tracks evidence, Architecture records accepted design |

Earlier ADR 0001–0016 versions remain in [pinned Git history](https://github.com/LuNa-shi/SwarmEnv/tree/02adbb43d39e0b23befb7f2ffc4b19ffb386a36d/docs/archive/2026-11-01/docs/adr). Historical decisions do not automatically control the latest system. New ADRs should state status, context, alternatives, decision and consequences, and link the approving GitHub Issue.
