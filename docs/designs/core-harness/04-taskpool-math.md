# TaskPool 数学形式化

[总览](README.md) · [Harness §6](02-harness.md#6-flat) · [执行票 #200](https://github.com/LuNa-shi/SwarmEnv/issues/200)

本修订承接上一轮延后的生产文件保存，恢复原版 [`fcbe0107`](https://github.com/LuNa-shi/SwarmEnv/commit/fcbe0107d8b4b204db0bcfa2a1ad1b2339c6293e) 的数学协作行为。迁移后对照基线为 [`ce3e503`](https://github.com/LuNa-shi/SwarmEnv/commit/ce3e503ba534d2b9cf42423aa0cdcdcc80766828)。[审核文档](https://github.com/LuNa-shi/SwarmEnv/blob/c840828cdcda16c565e6a6a3a19298b0a55f1204/docs/reviews/flat-formalization-comparison.md) 保留逐项差距及历史证据。本修订合入后约束 #200 的数学交付，历史范围与验收记录按各自固定版本解释。

## 普通入口

数学配置通过受支持的 TaskPool 入口装配 Mission、任务池、Workspace、固定题面、可信模型调用、实时文件保存和接续、Judge、Mathlib 查询、检查后合入及最终提交。各 Agent 从相同题面和公共初始版本出发，拥有不同的 Session 和私有目录。初始任务池为空。

保留普通 TaskPool 的显式宿主捕获和无捕获装配及其工具权限。入口根据实际装配公布可用工具。兼容路径运行现有任务收尾合同；数学配置按原题验收判定成功。

## 选工、责任和成果通知

- 选工时，Agent 可以查看包括运行中任务在内的公共状态并自发提案。正在执行的 Agent 可以发起其他 Agent 可认领的任务。由受信 Bridge 注入 Mission、Agent 和当前 Execution 身份，输入携带题意、具体交付条件、依赖和优先级等现有 Task 字段。提案来源不形成管理关系。
- 认领排他。Agent 先只读发现，经 take、固定输入版本、准备文件并续租、激活 Execution 后才取得写权限。一个 Agent 最多承担一个 Execution，可以在原 Session 中多轮编辑、检查、修正和接收成果。
- Agent 先保存有用文件并发布说明，再提交任务结束状态。结束可以表示完成、阻塞、取消或未完成。结束请求经接受后立即关闭该 Agent 的研究写入。确认执行停止后才解除原任务责任，确认清理后才复用槽位，新 Agent 从公开状态继续。
- 定向反馈与普通成果通知都核对当前 Task owner、Execution 和归属版本。普通通知从持久记录投递，在常规输入边界送达，保留稳定投递身份、去重和处理回执。结束后拒绝向失效归属投递，发送受理、模型实际看到、处理和采用分别留证。

## 文件保存与接续

- 生产 save 用 Core 捕获当前受权 Agent 的真实目录。稳定保存请求贯穿两层，校验文件路径、精确字节和摘要，捕获前后核对同一责任、租约与归属版本。文件操作序号与领域归属版本各自校验。原请求的回执未知时保留待核对状态并恢复同一次捕获，同 ID 变参拒绝，已完成发布可按原 ID 查询。
- apply 接收固定公共 revision，基于当前已保存版本做三方整合。检测未保存的改动，保留冲突和引入版本的来源，允许 Agent 后续解决冲突并再次保存。main 前进不会自动更改 Agent 的私有目录。
- 由受信宿主控制运行中安装。安装期间保护目录免受竞争写入，核对预期文件和安装结果，保存稳定请求与恢复信息。发生竞态、归属失效或安装回执未知时保持待核对或停止状态，禁止以未确认的目录继续研究。成功后继续同一 Agent、Execution 和 Session。Core 管文件访问与执行控制，TaskPool 管 Git 版本、归属、整合和冲突政策。
- 固定公共版本在 Agent 退出后仍可读。Material 引用确切版本和路径。只有检查通过且公共 main 仍处于检查所针对的基线时，才能推进 main。

## 数学检查、窗口与停止

- 集中 Judge 针对固定版本给出 Lean 项目或模块诊断，Agent 查询与检查工具链一致的 Mathlib 源码。合入检查使用候选和当前 main 合成后的全树，允许项目中暂时保留未完成工作。最终 Mission 检查固定原题、声明、候选树和工具链，校验证明依赖的公理并独立重放 Lean 内核。依赖 `sorry` 或未允许公理的目标不得通过。
- 原题已受理通过后停止研究并正常收尾。任务全部完成、取消或暂时清空时，只要 Mission 仍开放且有时间，就继续寻找工作。分别报告 Mission 验收、停止原因、候选和局部成果、用量以及执行和资源清理。
- 首轮用 [PutnamBench 2025 B1](https://github.com/trishullab/PutnamBench/blob/a635813f5edf297d928f9bd5ef8324a26bdde09c/lean4/src/putnam_2025_b1.lean)，固定题库 `a635813f5edf297d928f9bd5ef8324a26bdde09c`、目标 `putnam_2025_b1`、Lean 4.33.1、Mathlib `0df444a360eaa60ab8c11dca51a86af692955474`。Agent 可读原题和同版本 Mathlib。参考解、历史产物和人工拆好的子任务留在其可见范围之外。
- 首轮使用 `kimi_proxy/k3`、4 个同时工作的 Agent 槽位，环境就绪后最多 3,600 秒。更换 Agent 共享全场剩余时间。配置打通选工、任务、Agent 上限、软收尾和 checker 时限。本场不设请求数、Token 或费用上限，记录实际用量。截止时停止模型工作，冻结截止前已保存的候选，最终检查和清理另设有界时间、分别记录。正式跑次按[实验流程](../../workflows/experiment.md)固定实现、配置和证据，单独登记。

## 验收

1. 从实际安装包和普通入口测试空池提案、运行中列表、并发排他认领、准备与写入授权、模型调用领域权限、一 Agent 一责任、多轮续作、退场后补位。覆盖租约、归属失效、关闭竞态和先停止再补偿。
2. 用真实 Pi/OpenSandbox Agent 的 Bash 写入随机文本与二进制，保存并从公共 revision 回读真实字节及摘要。覆盖捕获或发布回执未知、同 ID 重试及变参、并发写入、停止、apply 冲突及恢复。证明同一 Session 持续执行、版本来源可追踪。
3. 用持久通知、Core Trace 和实际模型输入核对通知和定向反馈只到当前执行者，跨续轮去重并拒绝结束后投递。分别核对中间诊断、合成树检查、严格最终检查和任务池终态。保存公共成果、带时间戳的 Trace、独立清理回执和待核对状态。
4. 用实际 K3 从空池运行固定原题。完整通过要求至少一条「A 保存引理 → B 在原会话中接入并用于证明 → 进入固定最终 main」的跨 Agent 证据，且独立 checker 对同一固定版本验证原题。版本、源码和实际证明依赖共同支持采用结论。只有数学通过或只有协作证据时分别如实记录，完整验收仍未通过。
5. 同步实际入口、运行报告和 Architecture，包括工具、提示词、文件与状态合同、失败恢复、时限、停止、证据与清理。确定性回归、当前真实跑次和原版历史证据各自固定版本。
