# ScaleMAS 论文机制与 FATE 验收

[总览](README.md) · [Harness §7](02-harness.md#7-substrate) · [执行票 #202](https://github.com/LuNa-shi/SwarmEnv/issues/202)

本修订合入后规定 #202 的论文对齐配置及验收。原有通用示例与历史证据继续按各自固定版本解释。[固定审核](https://github.com/LuNa-shi/SwarmEnv/blob/66536e631fdea8cbf1a16bc7643c5b13433021d1/docs/reviews/scalemas-example-review.md) 记录原版论文、源码差距和评测来源，本文记录首轮交付范围。

## 普通入口与运行

- 从安装包普通 Substrate 入口启动 FATE 配置。固定数量的同级 Agent 在不同 Session、私有目录与 sandbox 中收到相同原题，自主查找、阅读、检查、发布与提交。宿主不派工、不广播成果、不追加要求发表的固定续轮。Core 管理 Agent、模型、Service 和收尾，Environment 管理协作、任务与截止时间。
- `shared` 同组共享库，`private` 按 Bridge 可信 Agent 身份隔离内容、索引统计、时钟和引用。两组开放相同的协作工具。`none` 只开放同样的解题工具和提交入口。三组独立启动，权限边界在 Service 执行，每次运行用新的目录与库。
- 每个 Agent 可显式提交并更新当前候选，宿主保留截止前最后一次确认提交。Agent 自然结束、提交并结束、失败或到时后，关闭该 Agent 的写入，其他 Agent 可继续。提交冻结后独立评分所有最终候选，任何一份通过即记团队成功。没有候选、超时、基础设施失败和清理 pending 均保留。
- 首轮固定 FATE-M [上游提交和原题](https://github.com/frenzymath/FATE-M/blob/4eb33c8ccd0ff058b461cd763cc406509129743f/FATE-M.json) ID 1，Lean 4.28.0，Mathlib `8f9d9cff6bd728b17a24e163c9402775d9e6a365`。模型为 `kimi_proxy/k3`，每组 4 Agent，三种条件按 shared、private、none 顺序各一次。Agent 就绪后每组最多 1,800 秒，全部结束可提前收尾。准备、复评、清理单独计时和设有界等待。记录实际模型用量，本场没有 K3 请求数、Token 或费用上限。按[实验流程](../../workflows/experiment.md)固定配置与登记跑次。

## 共享成果和任务工具

- 发布采用 `sub_task / artifact / rationale / refs` 四字段。每条引用由可见的既有消息或本题注册任务资源解析，理由必须明确包含引用地址及贡献说明；无效引用整次拒绝。sub_task 与 artifact 合计至多 1,024 tokens，至多 32 个引用。计数器及版本写入验收配置。内容只追加，原作者退出后仍可读取。发布请求重放保留原结果或明确拒绝，变更载荷冲突。
- search/visit 各最多返回八项，visit 每次最多八个地址；每项包含四字段、引用地址和至多八个最新入向消息地址。面向模型仅展示匿名记录。可信作者、原文、版本、时间与排序详情保存在宿主证据中。
- Unicode NFC 小写词项，BM25 索引子任务、产物和理由，使用 k1=1.5、b=0.75。只排序正相关项，分数为本次最高 BM25 归一化结果加引用权重，同分优先早发布。被引用消息权重增加 `0.3 × (1 − s)`，资源引用不加权。
- 每个新受理的 substrate 语义操作在可见库内推进一步。先对既有权重乘 0.98，再执行本次操作并增权。进入 Service 后被业务拒绝的新请求也推进，重放、同 ID 冲突和 Bridge 预校验拒绝不推进。private 库按 Agent 独立计时。宿主分别保存语义操作、原生工具和衰减记录。这是异步 Pi 对论文 group-step 的明确映射。
- 一场内每 Agent 可请求至多 100 次去重后的任务和共享库操作，其中工作中 Lean 检查至多 10 次，每次至多 900 秒且受本组剩余时间约束。相同请求重放不增加检查次数。Mathlib 查询只查固定库，至多 10 条。Agent 不能绕过 Service 接触 Lean checker 或可执行工具链。此工具边界与 K3 模型用量分别执行。
- 最终候选由宿主在全新隔离目录装入固定题面并独立编译。验证目标及前提仍与原题一致，拒绝 `sorry`、额外未证明公理、和编译错误。候选及摘要、作者、引用、结束原因、独立评分和资源回执由宿主保存。解题时只返回受配额的工作检查。

## 验收

1. 可重建冻结输入，独立检查器接收正确证明，拒绝编译错误、改题、占位和额外公理。模型目录不能影响题面和检查环境。
2. 验证匿名、有界读、排序加权和衰减、无效引用、重放、隔离、失败和清理 pending。从普通安装入口在原生环境证明 A 发布并实际释放资源后，B 在原 Session 读取确切原文、引用并用于后续成果。以带时间戳的记录核查可信作者、摘要、原始字节和资源状态。
3. 固定源码和配置完成首轮三组真实运行。每组可回溯候选或明确失败、独立评分及清理，且至少有一份正确证明走完整交付链路。真实任务采用按发布、读取、后继证明证据复核，若自然采用为零则如实报告。单题用于工程验收及协作复盘，100 题统计、额外 seed、论文模型接入和软件 benchmark 留给后续明确批准的工作。
4. 提供准备、从普通安装入口运行及独立重评路径。发布实现版本、测试结果与 Architecture，保留论文未公开的 harness 细节和本地适配差异。

## 单题长窗口验证

- 追加一轮 ScaleMAS 论文也使用的 FATE-H。三种条件使用同一份 [第 2 题原题](https://raw.githubusercontent.com/frenzymath/FATE-H/17967b3118082adfba7c5a5fc03b5f4a53717b59/FATE-H.json#L14)，固定上游提交 `17967b3118082adfba7c5a5fc03b5f4a53717b59`、Lean 4.28.0、同一 Mathlib 提交。原题要求证明阶数为 56 的群不是单群。对应已有的单题 FATE-M 配置和评分证据仍按各自的固定版本解释。
- K3、每组 4 Agent、shared、private、none 各一次，先登记再顺序启动。全员就绪后每组工作上限为 2,700 秒，仍按普通提交、退出和到时规则收尾。无 K3 用量上限。准备、清理、评分独立计时。
- 宿主在第 1,800 秒观察当时仍在工作的 Agent、提交摘要、工具记录和成果库活动。观察只写宿主证据，Agent 照常工作。提前结束按实际时长记录；未达到半小时、观察写入失败及正常取样分别记载。
- 核查选题、合法提交和独立评分。报告第 30 分钟、最后提交和结束时的进度，按成果原文、读取、引用和后继产物检查真实采用。自然采用为零、没有正确证明、或超过半小时仍未完成均保留实际结果。
